\# First Bad Version



\## 1. Problem

Есть n версий продукта, пронумерованных от 1 до n. Начиная с некоторой

версии `bad`, все последующие версии тоже «плохие» (bad), а все версии

до неё — «хорошие» (good). Дана функция `isBadVersion(version)`, которая

возвращает true/false. Нужно найти первую плохую версию, делая как можно

меньше вызовов этой функции.



\## 2. Approach

Так как версии упорядочены по принципу «сначала все good, потом все bad»,

использую бинарный поиск по диапазону \[1, n].

На каждом шаге беру середину `mid` и проверяю `isBadVersion(mid)`:

\- если true — значит первая плохая версия находится в левой половине

&#x20; (включая mid), сдвигаю правую границу: `right = mid`;

\- если false — первая плохая версия правее, сдвигаю левую границу:

&#x20; `left = mid + 1`.



Когда `left == right`, это и есть первая плохая версия.



\## 3. Time Complexity

Time Complexity: O(log n)

На каждой итерации диапазон поиска уменьшается вдвое, поэтому число

вызовов `isBadVersion` растёт как логарифм от n. Для n версий это

примерно log₂(n) проверок.



\## 4. Space Complexity

Space Complexity: O(1)

Используются только несколько переменных (`left`, `right`, `mid`),

дополнительная память не зависит от размера входа.



\## 5. Reflection / Improvement

Линейный перебор версий от 1 до n дал бы O(n) по времени. Бинарный

поиск уже оптимален для этой задачи, потому что использует монотонность

свойства «быть плохой версией». Улучшать по времени нечего; можно лишь

переписать итеративно ↔ рекурсивно, но рекурсия добавит O(log n) памяти

на стек вызовов, что хуже.
