\# Binary Search



\## 1. Problem

Дан отсортированный массив и целевое значение. Нужно вернуть индекс

целевого элемента или -1, если его нет.



\## 2. Approach

Использую два указателя `left` и `right`. На каждом шаге беру середину,

сравниваю её с целью и отбрасываю половину, где элемента точно нет.

Поиск продолжается, пока указатели не пересекутся.



\## 3. Time Complexity

Time Complexity: O(log n)

На каждом шаге область поиска уменьшается вдвое, поэтому число шагов

растёт как логарифм от n.



\## 4. Space Complexity

Space Complexity: O(1)

Используются только несколько переменных (left, right, mid), дополнительная

память не зависит от размера входа.



\## 5. Reflection / Improvement

Текущее решение уже оптимально по времени. Альтернатива — рекурсивный

вариант, но он даст O(log n) по памяти из-за стека вызовов, что хуже.
