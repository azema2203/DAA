&#x20;Palindrome Linked List



&#x20;Что делаю



Проверяю, является ли список палиндромом (читается одинаково слева направо и справа налево).



&#x20;Алгоритм (самый простой)



1\. Прохожу список и складываю все значения в ArrayList.

2\. Ставлю два указателя: left = 0, right = size - 1.

3\. Пока left < right:

&#x20;  - Если values\[left] != values\[right] - возвращаю false.

&#x20;  - Иначе left++, right--.

4\. Если дошли до середины - возвращаю true.



&#x20;Time Complexity



O(n)



&#x20;Space Complexity



O(n) - храню все значения в ArrayList.



&#x20;Почему так



Один проход по списку (n шагов) + один проход по массиву (n/2 шагов). В ArrayList лежат все n значений.



&#x20;Можно ли лучше



Да, можно за O(1) памяти:

1\. Найти середину через slow/fast указатели.

2\. Развернуть вторую половину списка на месте.

3\. Сравнить половины.



Но это заметно сложнее в коде. Для учебной задачи вариант с ArrayList честнее - видно идею "двух указателей с концов".



&#x20;Крайние случаи



\- Один узел -> true 

\- Два одинаковых -> true 

\- Два разных -> false 

\- Все одинаковые -> true
