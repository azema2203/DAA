Как это работает



&#x20;Делим массив пополам снова и снова пока не останутся кусочки по одному элементу

&#x20;Кусочек из одного элемента уже отсортирован - это факт

&#x20;Теперь начинаем склеивать кусочки обратно но уже по порядку

&#x20;При склейке двух отсортированных кусков сравниваем элементы по краям и берём меньший

&#x20;Кладём меньший во временный массив и двигаемся дальше

&#x20;Когда один кусок кончился - докидываем остатки второго

&#x20;Копируем временный массив обратно в исходный



Сложность по времени - O(n log n)

Почему log n

Потому что каждый раз массив делится пополам и глубина деления примерно log₂ n



Почему n на каждом уровне

Потому что на каждом уровне склейки мы проходим по всем n элементам ровно один раз



Итого n умножить на log n получаем O(n log n)

И это гарантировано в лучшем среднем и худшем случае - в отличие от быстрой сортировки которая может деградировать до O(n²)



Можно ли улучшить

По времени - нельзя

O(n log n) это доказанный минимум для сортировки сравнением

Никакой алгоритм на сравнениях не может быть быстрее



По памяти - у меня O(n) на временный массив

Это уже минимум среди алгоритмов с гарантированным O(n log n)

Есть вариант in-place сортировки слиянием с O(1) памяти но он либо медленный в худшем случае либо очень сложный в коде
