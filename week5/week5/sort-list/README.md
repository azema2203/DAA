Как это работает



&#x20;Сначала считаем сколько всего узлов в списке - это нужно чтобы знать сколько будет проходов

&#x20;Дальше идём проходами с шагом size равным 1 2 4 8 и так далее

&#x20;На каждом проходе берём пары кусков длиной size и сливаем их в один отсортированный кусок длиной 2 умножить на size

&#x20;Используем dummy узел - это фиктивная голова чтобы удобно перецеплять ссылки

&#x20;Метод split отрезает кусок ровно из n узлов и возвращает начало остатка

&#x20;Метод merge сливает два отсортированных списка и возвращает последний узел получившегося куска

&#x20;Через log n проходов весь список отсортирован



Сложность по времени - O(n log n)

Почему log n

Потому что размер куска удваивается каждый проход и нужно примерно log₂ n проходов чтобы покрыть весь список



Почему n на каждом проходе

Потому что за проход мы проходим каждый узел ровно один раз - через split и merge



Итого O(n log n) и это гарантировано в любом случае



Сложность по памяти - O(1)

Это самое главное в этой задаче



Нет рекурсии - значит нет стека вызовов

Нет новых узлов и нет массивов

Есть только несколько переменных указателей dummy prev cur left right

Мы только переставляем существующие ссылки next

Поэтому память действительно константная



Можно ли улучшить

По времени - нельзя

O(n log n) это доказанный минимум для сортировки сравнением

Быстрее в общем случае не получится



По памяти - уже O(1) то есть лучше некуда
