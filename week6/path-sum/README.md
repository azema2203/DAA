Решение рекурсивное. Иду от корня вниз, вычитая значение каждого узла из targetSum. Если узел null - false. Если это лист - проверяю, равно ли его значение оставшейся сумме. Иначе вычитаю значение узла и рекурсивно проверяю левое и правое поддеревья через ИЛИ - достаточно одного подходящего пути.



Ключевая деталь - проверка именно на лист, а не на null или remaining == 0 в середине. Путь обязан заканчиваться в листе, иначе путь с нужной суммой, но с детьми, не считается.



Сложность - O(n) в худшем случае (когда пути нет, обходим всё дерево), в лучшем случае находим раньше. Стек рекурсии - O(h). Улучшение - итеративная версия через стек с парами (узел, оставшаяся сумма), но она сложнее; при 5000 узлов рекурсия в большинстве случаев безопасна.
