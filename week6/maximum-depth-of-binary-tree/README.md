Моё решение - рекурсивное. В методе maxDepth сначала проверяю базовый случай если узел null, возвращаю 0 (пустое дерево имеет глубину 0). Иначе рекурсивно вычисляю глубину левого поддерева в переменную leftDepth и глубину правого поддерева в переменную rightDepth, беру максимум из них через Math.max и прибавляю 1 (за сам текущий узел). Возвращаю этот результат.



Алгоритм работает так: глубина дерева с корнем в узле - это 1 плюс максимум из глубин его левого и правого поддеревьев. Рекурсия спускается до листьев (у которых оба ребёнка null, поэтому их глубина = 1 + max(0, 0) = 1), а потом на обратном ходе «собирает» ответ снизу вверх. Каждый узел один раз сообщает наверх свою высоту, и корень в итоге получает максимальную глубину всего дерева.



Временная сложность - O(n), где n это количество узлов. Метод вызывается ровно один раз на каждый узел, и внутри каждого вызова выполняется O(1) работы: проверка на null, два рекурсивных вызова и одно сравнение через Math.max. Итого n вызовов умножить на O(1) даёт O(n). Стек рекурсии занимает O(h), где h - высота дерева (в худшем случае O(n) для вытянутого дерева, в лучшем O(log n) для сбалансированного).



Улучшить время нельзя  O(n) это минимум, ведь нужно посетить каждый узел, чтобы узнать максимальную глубину. Единственное улучшение - итеративная версия через BFS с очередью (Deque): обходим дерево по уровням, считаем количество уровней, это и будет глубина. У неё та же сложность O(n), но она защищает от StackOverflowError на очень глубоких деревьях (при ограничении в 10^4 узлов вытянутое дерево может дать глубину 10^4, что рискованно для рекурсии). Для учебных целей рекурсивная версия проще и понятнее.
