Решение рекурсивное. Создаю список result и вспомогательный метод traverse. Если узел null - выхожу. Иначе сначала добавляю значение узла в result, потом рекурсивно иду в левого ребёнка, потом в правого. В основном методе вызываю traverse(root, result) и возвращаю result. Список в Java передаётся по ссылке, поэтому добавления из вспомогательного метода видны в основном.



Preorder означает порядок «узел -> лево -> право»: сначала обрабатываем сам узел, а уже потом его поддеревья. Это главное отличие от inorder, где узел идёт между левым и правым.



Сложность - O(n): traverse вызывается ровно один раз на каждый узел, внутри O(1) работы (проверка на null, add, два рекурсивных вызова). Список result занимает O(n) памяти, но это выходные данные. Стек рекурсии - O(h), где h высота дерева. Улучшение - итеративная версия с явным стеком (Deque), защищающая от StackOverflowError на глубоких деревьях; при ограничении в 100 узлов рекурсия абсолютно безопасна.
